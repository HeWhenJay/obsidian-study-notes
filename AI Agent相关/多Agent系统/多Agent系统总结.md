## 核心结论

1. MAS 是多个自主 Agent 在共享环境中协作，不是简单复制多个 LLM 调用。
2. 多 Agent 适合市场研究、软件开发、智能营销、供应链、智能电网等天然需要分工的任务。
3. MAST 把常见失败归为规格问题、智能体间不对齐、任务验证问题。
4. 上下文工程要处理保存、选择、压缩、隔离四件事。
5. 框架选型不能只看评分，要看任务是对话协作、结构化流水线还是可控状态流。
