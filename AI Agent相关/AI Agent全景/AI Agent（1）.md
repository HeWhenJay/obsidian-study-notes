## 背景介绍

AI Agent 可以理解为“大模型应用从问答走向行动”的形态。普通 LLM 主要完成输入理解、推理和文本/代码/多媒体输出；AI Agent 则在 LLM 的基础上加入记忆、工具、规划和执行能力，使系统能够理解自然语言指令，感知当前环境，做出决策，并采取行动。

从课程前 24 页看，本节重点不是某个具体框架，而是建立 Agent 的整体认知：什么是 Agent、为什么普通 LLM 不够、Agent 的核心构成是什么，以及后续学习 Function Calling、MCP、LangChain 等工具链时应该放在哪个位置理解。

## 课程环境和前置

- Python 版本：3.11。
- 课程会使用 LangChain，但本章为了讲清底层原理，使用的是 LangChain V0.3，而不是当前更新后的 V1.0。
- 大模型平台建议采用兼容 OpenAI 接口规范的平台，课程中建议使用阿里云百炼。
- API-KEY 不建议直接写在代码里，应统一放在操作系统环境变量中，再由代码读取。
- 如果使用 TavilySearchResults 搜索工具，需要注册 Tavily，并将 API Key 配置到系统环境变量 `TAVILY_API_KEY`。

前置知识包括计算机通识、Python 基础、PyCharm 基本使用、L1/L2 阶段的大模型应用基础、第三方平台 Key 申请与环境变量配置等。

## AI Agent核心定义

AI Agent 是基于 LLM 的、能够自主理解、感知、规划决策并执行复杂任务的智能体。

它适合处理普通语言模型难以直接解决的问题，尤其是下面这类任务：

1. 任务需要多个步骤才能完成。
2. 任务需要外部工具参与，例如搜索、计算器、代码解释器、日历等。
3. 任务需要外部数据源，例如网页、数据库、知识库或业务系统。
4. 任务过程中需要根据中间结果继续调整计划。

可以用一个公式理解：

```text
AI Agent = LLM + 记忆 + 工具 + 规划 + 执行
```

其中 LLM 提供语言理解、推理和生成能力；记忆提供上下文和历史经验；工具让 Agent 能访问外部能力；规划决定任务怎么拆、怎么做、什么时候停止；执行负责把计划落实为具体动作。

## 与普通LLM的区别

普通 LLM 更像“会思考和表达的大脑”，能根据输入生成回答，但它本身不一定能主动调用外部工具，也不一定能持续管理任务过程。

AI Agent 更像“带行动能力的任务执行者”，它不只回答问题，还能围绕目标完成一系列操作。例如用户问“现任美国总统年龄的平方是多少”，普通 LLM 可能直接尝试回答；Agent 更合理的流程是先确认现任总统是谁，再查询年龄，再调用计算能力得到平方结果。

所以 Agent 的关键不只是“回答更聪明”，而是能把问题转化为可执行流程。

## AI Agent四大要素和架构

### 规划（Planning）

规划可以理解为观察、思考和计划。Agent 接到任务后，需要先判断如何完成任务，再审视可用工具，把复杂任务拆成子任务，并在执行过程中反思和修正。

规划能力通常包含：

- 任务分解：把大任务拆成更小、更可控的子任务。
- 工具选择：判断当前步骤是否需要搜索、计算、代码执行或其他工具。
- 自我反思：根据执行结果检查是否偏离目标，并修正后续步骤。
- 终止判断：判断任务何时已经完成，避免无限循环或过度执行。

课程中强调，大模型赋予 Agent 的规划和执行能力是 Agent 架构中的重点。常见规划技术包括任务分解、自我反思、结合外部规划器等。

### 记忆（Memory）

Agent 的记忆主要来自三类：

1. 大模型的预训练与微调：模型参数中已经学习到的通用知识和能力。
2. 上下文：当前对话、当前任务过程中的短期信息。
3. 外部记忆库：可持久化保存和检索的信息，例如向量库、数据库、历史任务记录等。

短期记忆适合维持当前任务状态，长期记忆适合跨会话复用用户偏好、历史经验和业务知识。

### 工具（Tools）

工具调用能力是 Agent 的核心技能之一。工具可以为 Agent 提供额外的数据、处理能力和专业资源，使 Agent 能完成更复杂的任务。

常见工具包括：

- Search：搜索外部信息。
- Calculator：执行精确计算。
- CodeInterpreter：运行代码、处理文件或分析数据。
- Calendar：读取或管理日程。
- 更多业务工具：数据库查询、工单系统、知识库、办公软件、内部 API 等。

Function Calling 是工具调用的典型范例，MCP 也是 Agent 工具调用方向的重要进展。

### 执行（Execution）

执行是把规划结果转化为具体动作。Agent 不应只停留在“想好了怎么做”，还要调用工具、读取结果、更新状态，并根据结果继续下一步。

一个完整 Agent 往往会形成循环：

```text
用户目标 -> 规划 -> 工具调用/执行 -> 观察结果 -> 反思修正 -> 继续执行或结束
```

## 任务拆解

任务拆解是 Agent 完成复杂任务的基础能力。通过 LLM，Agent 可以把大型任务拆成更小、更可控的子任务，从而降低一次性推理的难度。

例如一个复杂问题可能需要：

1. 先明确用户真实目标。
2. 再拆成若干可检索、可计算或可执行的步骤。
3. 分别调用工具完成每个步骤。
4. 汇总中间结果，生成最终答案。

这也是后续学习 ReAct、Plan-and-Execute、LangGraph 等 Agent 编排方式的基础。

## 常见实例

课程中提到的智能体实例包括金融类智能体“支小助/蚂小财”。这类应用说明 Agent 不只是聊天机器人，而是面向具体业务场景，把用户自然语言目标转化为业务操作、信息查询、建议生成或辅助决策。

需要注意：AI Agent 易学易用，但难用好。真正落地时，难点通常不在“能不能调起一个 Agent 框架”，而在任务边界、工具设计、状态管理、错误恢复、权限控制和效果评估。

## 小结

AI Agent 的核心价值是把 LLM 从“回答问题”扩展到“完成任务”。它依赖 LLM 的推理能力，但真正形成 Agent 还需要记忆、工具、规划和执行闭环。

学习 Agent 时可以抓住一条主线：

```text
LLM负责思考和表达
记忆负责保留上下文和经验
工具负责连接外部世界
规划负责拆解和决策
执行负责把计划变成动作
```

后续学习 Function Calling、MCP、LangChain、LangGraph、Dify/Coze 等内容时，都可以放回这条主线中理解。
