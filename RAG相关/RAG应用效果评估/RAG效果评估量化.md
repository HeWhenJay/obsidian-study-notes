## 简介

### 必要性

当准备将一个 RAG 应用投入生产或上线使用时，需要考虑以下问题：

1. 大模型输出具有一定的不确定性，RAG 应用上线前需要用科学测量来评估这种不确定性带来的风险。
2. RAG 应用上线后需要持续维护，因此要有科学、快速、可复用的手段来判断改进是否有效，以及效果提升有多少。
3. RAG 应用依赖的外部知识库通常会动态更新，新文档、新数据可能影响旧问题的回答效果，因此需要定期检测和重新评估。
4. RAG 应用依赖基础模型，需要评估不同商业模型、开源模型或模型版本升级对当前项目的影响。

### 方法

**人工评估：** RAG 应用评估的基础方法，即邀请专家或人工评估员对 RAG 生成结果进行质量评估，通常关注准确性、连贯性、相关性等。人工评估质量较高，但耗时耗力，成本高，也受评估员主观性和经验差异影响。

**自动化评估：** RAG 应用评估的主流方式之一，常与人工评估结合使用。它利用 LLM、embedding 模型和相关算法对 RAG 输出进行评分，从而快速评估系统表现，降低评估成本，并便于多版本对比。

## 评估依据和指标

### 简介

RAG 应用不同于传统应用的固定输出，它的输入和输出通常都是自然语言，难以只靠简单规则定量评估相关性和准确性。因此，RAG 评估通常需要借助评估模型、测试集和自动化评估工具。

任何 RAG 系统的有效性和性能都依赖两个核心组件：**检索器和生成器**。

检索器负责识别和召回与问题相关的文档，生成器负责基于检索出的上下文生成连贯、相关、准确且忠实的回答。部署前分别评估这两个组件，有助于确认 RAG 应用的性能和可靠性。

### 评估方法

- 检索评估：主要评估检索到的上下文与用户问题、参考答案之间的匹配程度，确保提供给生成器的上下文相关、完整且排序合理。详见：[[RAG检索评估]]
- 响应评估：主要评估生成组件，衡量系统能否基于检索到的上下文生成忠实、相关、完整的回答。详见：[[RAG响应评估]]

### 评估依据包含的要素

1. 输入问题（question / user_input）：用户在使用 RAG 时输入的问题。
2. 生成答案（answer / response）：需要评估的 RAG 输出。
3. 上下文（context / retrieved_contexts）：检索阶段返回、用于增强回答的参考材料。
4. 参考答案（reference answer / ground truth）：输入问题的标准答案，通常需要人工标注。

基于这些依据，对 RAG 进行评估时，常见指标如下：

- 上下文相关性（Context Relevance / Context Relevancy）
- 上下文精度（Context Precision）
- 上下文召回率（Context Recall）
- 忠实度（Faithfulness）
- 答案/响应相关性（Answer Relevancy / Response Relevancy）
